# 학교 리그 서버 설정 (Supabase)

리그를 **실제로** 여러 반·학교가 겨루는 판으로 만들려면 서버가 하나 필요합니다.
이 폴더의 SQL 파일을 아래 순서로 Supabase 에 올리고, 앱에 주소와 anon 키를 넣으면 됩니다.

서버를 설정하지 않아도 앱은 그대로 동작합니다. 그때 리그에는
이 브라우저의 내 기록과 예전에 저장해 둔 로컬 그룹 기록만 나옵니다.

---

## 1. 프로젝트 만들기

1. https://supabase.com 에서 프로젝트를 만듭니다 (무료 티어로 충분합니다).
2. 리전은 **Northeast Asia (Seoul)** 을 고르면 국내에서 가장 빠릅니다.

> ⚠️ 계정 생성과 로그인은 직접 하셔야 합니다.

## 2. 스키마 올리기

대시보드 왼쪽 **SQL Editor** → **New query** 에 아래 파일을 순서대로 붙여 넣고 **Run**.

1. `schema.sql` — 학교 리그와 기본 학급 집계
2. `schema_admin.sql` — 별도 동의한 학생 기록과 관리자 권한
3. `schema_class_league.sql` — 반 대항 공개·닉네임·숨김 설정·관리자 삭제
4. `schema_admin_league.sql` — 관리자가 익명 리그 참가자를 볼 수 있는 권한
5. `schema_league_notes.sql` — 우리 반 포스트잇 (10~30분 뒤 사라지는 쪽지)

5번을 올리지 않으면 앱의 포스트잇 기능만 동작하지 않습니다(리그는 그대로입니다).
쪽지를 붙일 때 "붙이지 못했습니다 — HTTP 404" 가 뜬다면 이 파일을 안 올린 것입니다.

관리자 화면을 쓸 경우 Authentication에서 계정을 만든 뒤 `register-admin.sql`을 실행하고,
`verify-admin.sql`로 등록 결과를 확인합니다.

여러 번 실행해도 안전합니다. **다만 순서는 지켜야 합니다** — `schema.sql` 안의
`revoke all on public.league_report from anon, authenticated` 가
`schema_admin_league.sql` 이 관리자에게 준 select 권한까지 함께 지웁니다.
**`schema.sql` 을 나중에 다시 실행했다면 `schema_admin_league.sql` 도 반드시 다시 실행하세요.**

### 관리자 화면이 "읽을 권한이 없습니다 / 테이블이 없습니다" 라고 할 때

| 증상 | 원인 | 할 일 |
|---|---|---|
| 익명 참가자 목록이 403 | 4번 미실행, 또는 그 뒤에 `schema.sql` 재실행 | `schema_admin_league.sql` 다시 실행 |
| 학생 목록이 404 | 2번 미실행 (`student_report` 없음) | `schema_admin.sql` 실행 |
| 목록은 뜨는데 **비어 있음** | 권한은 정상. 관리자 계정이 `admins` 에 없거나 아직 아무도 공유하지 않음 | `verify-admin.sql` 로 등록 확인 |

마지막 줄이 중요합니다 — 관리자 등록이 안 된 경우는 **오류가 아니라 빈 목록**으로 나옵니다.
RLS 가 행만 걸러 내므로 요청 자체는 성공(HTTP 200)하기 때문입니다.

이 SQL 이 하는 일:

| 대상 | 내용 |
|---|---|
| `league_report` | 원본 테이블. **RLS 로 잠겨 있어 아무도 직접 읽거나 쓸 수 없습니다.** |
| `school_week` | 학교별 합계만 내보내는 뷰. 읽기 공개. |
| `class_week` | 학급별 합계. 5명 미만 학급은 나오지 않습니다. `schema_class_league.sql` 실행 후 공개. |
| `class_week_pending` | 5명 미만 학급의 참가 인원만 공개. 합계 시간은 공개하지 않음. |
| `class_members()` | 같은 반 참가자의 닉네임·시간을 반환. 숨긴 사용자는 본인 외에는 제외. |
| `student_report` | 관리자 공개에 따로 동의한 학생의 닉네임·학교·학습 시간. |
| `class_audit` | 학급별 조작 의심 신호. **운영자 전용(비공개).** |
| `device_seen` | 기기가 처음 나타난 날짜와 올린 횟수. **운영자 전용(비공개).** |
| `event_class` | 이벤트 참가 신청 학급 명단. 운영자가 직접 채웁니다. |
| `report_league()` | 유일한 쓰기 통로. 값 검증 후 저장합니다. |
| `delete_own_league_reports()` | 학교·학급 리그 동의 철회 시 해당 기기의 리그 기록 삭제. |
| `delete_own_student_reports()` | 관리자 공개 동의 철회 시 해당 기기의 개별 기록 삭제. |
| `purge_old_reports()` | 60일 지난 기록 삭제. |
| `class_note` | 우리 반 포스트잇. **RLS 로 잠겨 있고** 아래 함수로만 오갑니다. 최대 수명 30분. |
| `post_class_note()` | 쪽지 붙이기. 수명 10~30분, 1인 5장, 8초 간격 제한. 부를 때마다 만료된 행을 지웁니다. |
| `fetch_class_notes()` | 같은 반의 살아 있는 쪽지 최대 40장. |
| `move_class_note()` · `remove_class_note()` | 자리 옮기기·떼기. **본인 기기의 쪽지만** 됩니다. |
| `admin_clear_notes()` | 신고가 들어왔을 때 운영자가 지웁니다. 관리자 로그인 필요. |

> 쪽지의 **욕설 필터는 서버가 아니라 앱**(`src/js/filter.js`)에 있습니다. 같은 목록을
> 두 곳에 두면 규칙이 어긋나고 느슨한 쪽만 쓰이게 되기 때문입니다. 서버는 길이·개수·시간만
> 봅니다. 앱은 화면에 그릴 때도 한 번 더 걸러, 다른 통로로 들어온 글을 가립니다.

### 학급 대항전 이벤트를 연다면

1. 참가 신청을 따로 받습니다(구글폼 등). 앱은 이름·연락처를 모으지 않으므로,
   우승해도 연락할 방법이 신청서 말고는 없습니다.
2. 받은 명단을 `event_class` 에 넣습니다.

   ```sql
   insert into public.event_class (school, level, grade, klass, contact)
   values ('한빛고등학교', '고등학교', '2', '7', '010-0000-0000');
   ```
3. 정산할 때는 `schema.sql` 하단 주석의 조회 쿼리를 씁니다.
   `new_devices` · `few_reports` · `near_cap` 을 반드시 같이 보세요.

> ⚠️ 익명 키는 앱 안에 들어 있고 로그인이 없습니다. 그래서 누구나 REST 로
> 직접 기록을 올릴 수 있고, 이것은 **구조상 막을 수 없습니다.** 위 장치들은
> 조작을 어렵게 만들고 흔적을 남길 뿐입니다. 상품이 걸린 순위는 반드시
> 사람이 확인하고 확정하세요.

## 3. 앱에 연결하기

대시보드 **Settings → API** 에서 두 값을 복사해
`src/js/cloud.js` 맨 위에 넣습니다.

```js
var SUPABASE_URL = 'https://xxxxxxxxxxxx.supabase.co';
var SUPABASE_ANON_KEY = 'eyJhbGciOi...';
```

그리고 빌드합니다.

```bash
powershell -ExecutionPolicy Bypass -File build.ps1
```

> **anon 키를 소스에 넣어도 되나요?** — 네. anon 키는 공개를 전제로 설계된 값입니다.
> 정적 사이트라 어차피 브라우저에 노출됩니다. 그래서 이 스키마는 키가 공개된 상태를
> 가정하고 RLS 로 테이블을 잠근 뒤 검증 함수 하나만 열어 뒀습니다.
> **`service_role` 키는 절대 넣지 마세요.** 그 키는 모든 보안 정책을 무시합니다.

select public.purge_old_reports();

## 전송되는 데이터

학교 리그를 **켠 사용자만** 아래 값을 보냅니다.

```json
{ "p_device": "8744db45-…", "p_week": "2026-07-27",
  "p_school": "대현중학교", "p_minutes": 450 }
```

- `p_device` — 무작위 UUID. 같은 기기를 두 번 세지 않기 위한 값입니다.
- `p_week`, `p_school`, `p_minutes` — 주차·학교명·주간 순공 시간입니다.
- `p_hidden` — 학급 순위에서 내 줄을 숨길지 나타내는 값입니다.

학급 대항전에 따로 동의하면 학교급·학년·반·닉네임이 추가됩니다. 동의를 끄면 다음 동기화에서
이 값들을 빈 값으로 덮어 서버에 남아 있던 학급 정보를 지웁니다.

포스트잇을 붙이면 `class_note` 에 쪽지 내용·닉네임·학교급·학년·반·색·붙인 자리·사라질 시각이
저장됩니다. 같은 학교·학년·반이면 읽을 수 있고, 길어야 30분이면 서버에서 지워집니다.
쪽지를 붙이지 않으면 아무것도 저장되지 않습니다.

관리자 공개에 따로 동의하면 `student_report`에 무작위 기기 번호·주차·닉네임·학교명·순공 시간이 저장됩니다.
이 목록은 등록된 관리자 계정으로 로그인한 사용자만 읽을 수 있습니다.

각 공유 스위치를 끄면 새 전송을 즉시 중단하고 해당 범위의 서버 기록을 삭제합니다.
삭제 요청이 연결 문제로 실패하면 브라우저에 요청을 보관하고 다음 실행 때 다시 시도합니다.
익명 서비스이므로 무작위 기기 UUID가 삭제 권한표 역할을 하며, UUID를 버리기 전에 서버 삭제 성공을 확인합니다.

과목·시험 일정·뇌 컨디션 점수·수면/스트레스 입력값은 **전송되지 않습니다.**

## 알아 두어야 할 한계

- **익명 쓰기입니다.** 로그인이 없으므로 마음먹으면 없는 학교의 시간을 부풀릴 수 있습니다.
  스키마에서 1인 주당 2100분 상한, 감소 불가, 35일 밖 주차 거부로 피해를 제한했지만
  완전히 막으려면 로그인이 필요합니다.
- **켠 사람만 집계됩니다.** 학교의 실제 총 학습량보다 적게 나옵니다.
- 학생 이용자는 만 14세 이상으로 제한하며, 초등 기능은 보호자가 사용하는 학부모 모드로 제공합니다. 학부모 모드에서는 자녀 정보를 서버로 전송하는 리그·관리자 공개 기능을 사용할 수 없습니다.
  학급 대항전과 관리자 공개는 닉네임·학교·학년·반 조합으로 개인이 추정될 수 있습니다.
  실제 서비스로 배포한다면 개인정보 처리방침·보유 기간·삭제 절차를 두고 법률 검토를 받으세요.
