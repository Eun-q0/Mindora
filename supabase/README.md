# 학교 리그 서버 설정 (Supabase)

리그를 **실제로** 여러 학교가 겨루는 판으로 만들려면 서버가 하나 필요합니다.
이 폴더의 `schema.sql` 을 Supabase 에 올리고, 앱에 주소와 키를 넣으면 됩니다.

서버를 설정하지 않아도 앱은 그대로 동작합니다. 그때 리그에는
이 브라우저가 아는 학교(우리 학교 + 공유 코드로 등록한 학교)만 나옵니다.

---

## 1. 프로젝트 만들기

1. https://supabase.com 에서 프로젝트를 만듭니다 (무료 티어로 충분합니다).
2. 리전은 **Northeast Asia (Seoul)** 을 고르면 국내에서 가장 빠릅니다.

> ⚠️ 계정 생성과 로그인은 직접 하셔야 합니다.

## 2. 스키마 올리기

대시보드 왼쪽 **SQL Editor** → **New query** 에 `schema.sql` 전체를 붙여 넣고 **Run**.

여러 번 실행해도 안전합니다.

이 SQL 이 하는 일:

| 대상 | 내용 |
|---|---|
| `league_report` | 원본 테이블. **RLS 로 잠겨 있어 아무도 직접 읽거나 쓸 수 없습니다.** |
| `school_week` | 학교별 합계만 내보내는 뷰. 읽기 공개. |
| `class_week` | 학급별 합계. 5명 미만 학급은 나오지 않습니다. **운영자 전용(비공개).** |
| `class_audit` | 학급별 조작 의심 신호. **운영자 전용(비공개).** |
| `device_seen` | 기기가 처음 나타난 날짜와 올린 횟수. **운영자 전용(비공개).** |
| `event_class` | 이벤트 참가 신청 학급 명단. 운영자가 직접 채웁니다. |
| `report_league()` | 유일한 쓰기 통로. 값 검증 후 저장합니다. |
| `purge_old_reports()` | 60일 지난 기록 삭제. |

### 학급 대항전 이벤트를 연다면

1. 참가 신청을 따로 받습니다(구글폼 등). 앱은 이름·연락처를 모으지 않으므로,
   우승해도 연락할 방법이 신청서 말고는 없습니다.
2. 받은 명단을 `event_class` 에 넣습니다.

   ```sql
   insert into public.event_class (school, level, grade, klass, contact)
   values ('한빛고등학교', '고등학교', '2', '7', '010-0000-0000');
   ```
3. 정산할 때는 `schema.sql` 하단 주석의 조회 쿼리를 씁니다.
   `new_devices` · `few_reports` · `near_cap` 을 반드시 같이 보세요.

> ⚠️ 익명 키는 앱 안에 들어 있고 로그인이 없습니다. 그래서 누구나 REST 로
> 직접 기록을 올릴 수 있고, 이것은 **구조상 막을 수 없습니다.** 위 장치들은
> 조작을 어렵게 만들고 흔적을 남길 뿐입니다. 상품이 걸린 순위는 반드시
> 사람이 확인하고 확정하세요.

## 3. 앱에 연결하기

대시보드 **Settings → API** 에서 두 값을 복사해
`src/js/cloud.js` 맨 위에 넣습니다.

```js
var SUPABASE_URL = 'https://xxxxxxxxxxxx.supabase.co';
var SUPABASE_ANON_KEY = 'eyJhbGciOi...';
```

그리고 빌드합니다.

```bash
powershell -ExecutionPolicy Bypass -File build.ps1
```

> **anon 키를 소스에 넣어도 되나요?** — 네. anon 키는 공개를 전제로 설계된 값입니다.
> 정적 사이트라 어차피 브라우저에 노출됩니다. 그래서 이 스키마는 키가 공개된 상태를
> 가정하고 RLS 로 테이블을 잠근 뒤 검증 함수 하나만 열어 뒀습니다.
> **`service_role` 키는 절대 넣지 마세요.** 그 키는 모든 보안 정책을 무시합니다.

## 4. 확인

앱 → **설정 → 학교 리그 참가 → 연결 확인**

## 5. 오래된 기록 정리 (선택)

**Database → Cron** 에서 주 1회 예약:

```sql
select public.purge_old_reports();
```

## 전송되는 데이터

리그를 **켠 사용자만**, 아래 네 가지만 보냅니다.

```json
{ "p_device": "8744db45-…", "p_week": "2026-07-27",
  "p_school": "대현중학교", "p_minutes": 450 }
```

- `p_device` — 무작위 UUID. 같은 사람을 두 번 세지 않기 위한 값이며 이름·학년과 무관합니다.
  앱에서 **기기 번호 새로 받기** 를 누르면 이전 기록과 연결이 끊깁니다.
- 이름·학년·반·과목·시험 일정·뇌 컨디션 점수·수면/스트레스 입력값은 **전송되지 않습니다.**

## 알아 두어야 할 한계

- **익명 쓰기입니다.** 로그인이 없으므로 마음먹으면 없는 학교의 시간을 부풀릴 수 있습니다.
  스키마에서 1인 주당 2100분 상한, 감소 불가, 35일 밖 주차 거부로 피해를 제한했지만
  완전히 막으려면 로그인이 필요합니다.
- **켠 사람만 집계됩니다.** 학교의 실제 총 학습량보다 적게 나옵니다.
- **만 14세 미만 아동의 개인정보를 수집하려면 법정대리인 동의가 필요합니다.**
  현재 설계는 개인을 식별하지 않는 집계만 다루도록 범위를 좁혔지만,
  실제 서비스로 배포한다면 개인정보 처리방침을 두고 법률 검토를 받으시길 권합니다.
